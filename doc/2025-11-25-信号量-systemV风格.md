# 信号量设计思路文档

## 1. 概述

信号量是一种用于进程间同步和互斥的重要机制。在本系统中，我们实现支持System V IPC信号量接口的信号量，包括[semget](../arch/riscv/user/user.h#L72-L72)、[semop](../arch/riscv/user/user.h#L73-L73)和[semctl](../arch/riscv/user/user.h#L74-L74)三个核心系统调用。

## 2. 设计架构

### 2.1 数据结构

信号量系统主要包含以下数据结构：

1. **信号量(`semaphore`)**：
   ```c
   struct semaphore {
     int value;     // 信号量值
     int pid;       // 最后操作该信号量的进程ID
   };
   ```

2. **信号量集([sem_set](../arch/riscv/kernel/proc.h#L121-L130))**：
   ```c
   struct sem_set {
     int used;                      // 是否正在使用
     int refcnt;                    // 引用计数
     int semid;                     // 信号量集标识符
     int marked_for_deletion;       // 标记为删除
     int nsems;                     // 信号量数量
     struct semaphore sems[MAX_SEMS_PER_SET]; // 信号量数组
     struct spinlock lock;          // 保护信号量集的锁
   };
   ```

3. **信号量操作([sembuf](../arch/riscv/kernel/proc.h#L133-L137))**：
   ```c
   struct sembuf {
     short sem_num;  // 信号量编号
     short sem_op;   // 操作值
     short sem_flg;  // 操作标志
   };
   ```

### 2.2 锁机制

为了避免死锁，系统严格按照以下锁获取顺序：
进程锁(p->lock) → 全局锁(sem_lock) → 信号量集锁(set.lock)

## 3. 核心系统调用实现

### 3.1 `semget` - 获取信号量集

功能：创建一个新的信号量集或获取一个已存在的信号量集。

参数：
- [key](../arch/riscv/kernel/proc.h#L124-L124): 信号量集的键值
- [nsems](../arch/riscv/kernel/proc.h#L125-L125): 信号量集中信号量的数量
- `semflg`: 控制创建行为的标志

实现要点：
1. 搜索是否存在具有相同[key](../arch/riscv/kernel/proc.h#L124-L124)的信号量集
2. 如果不存在且设置了IPC_CREAT标志，则创建新的信号量集
3. 如果存在，则检查[nsems](../arch/riscv/kernel/proc.h#L125-L125)参数是否与现有信号量集匹配

### 3.2 [semop](../arch/riscv/user/user.h#L73-L73) - 信号量操作

功能：对信号量集中的一个或多个信号量执行操作。

参数：
- [semid](../arch/riscv/kernel/proc.h#L123-L123): 信号量集标识符
- `sops`: 指向[sembuf](../arch/riscv/kernel/proc.h#L133-L137)结构数组的指针
- `nsops`: `sops`数组中的操作数

实现要点：
1. 支持三种类型的操作：
   - `sem_op > 0`: 释放资源（V操作），将[sem_op](../arch/riscv/kernel/proc.h#L135-L135)加到信号量值上
   - `sem_op < 0`: 请求资源（P操作），从信号量值中减去abs([sem_op](../arch/riscv/kernel/proc.h#L135-L135))
   - `sem_op = 0`: 等待信号量值变为0

2. 支持阻塞和非阻塞模式（通过[sem_flg](../arch/riscv/kernel/proc.h#L136-L136)中的IPC_NOWAIT标志）

3. 实现了睡眠和唤醒机制，当进程需要等待时会进入睡眠状态

### 3.3 [semctl](../arch/riscv/user/user.h#L74-L74) - 信号量控制

功能：对信号量集执行各种控制操作。

参数：
- [semid](../arch/riscv/kernel/proc.h#L123-L123): 信号量集标识符
- `semnum`: 信号量编号
- [cmd](../arch/riscv/test-xv6.py#L53-L57): 控制命令
- `arg`: 命令参数

支持的命令：
- [GETVAL](../arch/riscv/kernel/proc.h#L159-L160): 获取信号量值
- [SETVAL](../arch/riscv/kernel/proc.h#L160-L161): 设置信号量值
- [IPC_RMID](../arch/riscv/kernel/proc.h#L156-L157): 删除信号量集
- [IPC_STAT](../arch/riscv/kernel/proc.h#L166-L167): 获取信号量集信息

## 4. 使用说明

### 4.1 基本使用流程

1. **创建或获取信号量集**：
   ```c
   int semid = semget(key, nsems, IPC_CREAT | 0666);
   ```

2. **初始化信号量值**：
   ```c
   int value = 1;
   semctl(semid, 0, SETVAL, &value);
   ```

3. **执行P操作（等待）**：
   ```c
   struct sembuf op_p = {0, -1, 0};
   semop(semid, &op_p, 1);
   ```

4. **执行V操作（释放）**：
   ```c
   struct sembuf op_v = {0, 1, 0};
   semop(semid, &op_v, 1);
   ```

5. **删除信号量集**：
   ```c
   semctl(semid, 0, IPC_RMID, 0);
   ```

### 4.2 多信号量操作示例

```c
struct sembuf ops[] = {
    {0, -1, 0}, // 对第0个信号量执行P操作
    {1, 1, 0},  // 对第1个信号量执行V操作
    {2, -1, 0}  // 对第2个信号量执行P操作
};
semop(semid, ops, 3);
```

### 4.3 死锁预防

在使用多个信号量时，为避免死锁，请确保所有进程按照相同的顺序获取信号量。例如：

```c
// 所有进程都应该按照相同的顺序获取信号量
// 先获取semid1，再获取semid2
semop(semid1, &op1, 1);
semop(semid2, &op2, 1);
```

## 5. 测试验证

系统包含多种测试用例来验证信号量功能：

1. **基本功能测试**：测试信号量的创建、初始化、P/V操作和删除
2. **进程同步测试**：验证父子进程之间的同步
3. **多信号量测试**：测试对多个信号量的同时操作
4. **压力测试**：大量并发进程测试信号量的稳定性和性能

## 6. 注意事项

1. **资源管理**：使用完毕后务必删除信号量集，避免资源泄露
2. **错误处理**：检查所有系统调用的返回值，处理可能的错误情况
3. **死锁预防**：在使用多个信号量时，始终按照固定顺序获取资源
4. **并发安全**：在多进程环境中，使用信号量保护共享资源的访问
