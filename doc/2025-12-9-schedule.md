# RR 调度器实现文档

## 概述

RR (Round Robin) 调度器是一种时间片轮转调度算法，它为每个进程分配固定的时间片，当时间片用完后，将 CPU 转交给下一个就绪进程。

## 实现原理

### 1. 系统调用

- **系统调用号**: 400 (在 `sysnum.h` 中定义)
- **系统调用名**: `set_timeslice`
- **功能**: 设置当前进程的时间片长度
- **参数**: 时间片值 (必须 ≥ 1)
- **返回值**: 成功返回 0，失败返回 -1

### 2. 内核数据结构

在 `proc` 结构体中添加了以下字段:
```c
#ifdef SCHEDULER_RR
int timeslice;        // 进程的时间片长度
int slice_remaining;  // 剩余时间片
#endif
```

### 3. 核心函数

#### `sys_set_timeslice()`
- 位置: `arch/riscv/kernel/sysproc.c`
- 功能: 系统调用处理函数，设置当前进程的时间片
- 参数校验: 确保时间片值 ≥ 1

#### `rr_on_timer_tick()`
- 位置: `arch/riscv/kernel/proc.c`
- 功能: 处理时钟中断，递减剩余时间片，时间片耗尽时触发进程切换
- 调用时机: 在 `trap.c` 的时钟中断处理中调用

### 4. 调度器行为

- 默认调度器: 每次时钟中断时当前进程立即让出 CPU
- RR 调度器: 只有当进程时间片耗尽时才让出 CPU

## 编译与使用

### 编译选项
在 `Makefile` 中添加 `-DSCHEDULER_RR` 编译标志启用 RR 调度器:
```makefile
CFLAGS += -DSCHEDULER_RR
```

### 用户程序使用
```c
#include "user/user.h"

int main() {
    // 设置当前进程的时间片为 5 个时钟节拍
    set_timeslice(5);
    
    // 执行任务...
    
    exit(0);
}
```

## 测试程序

`rrtest.c` 提供了全面的测试用例，包括:
- 基本 RR 调度功能测试
- 长时间运行任务测试
- 不同时间片设置影响测试
- 错误参数处理测试
- 多级 fork 场景测试

## 注意事项

1. 时间片值必须 ≥ 1，否则系统调用返回 -1
2. 时间片单位是时钟中断节拍数
3. 子进程继承父进程的时间片设置
4. RR 调度器通过条件编译实现，不影响默认调度器

# 优先级调度器实现文档

## 概述

优先级调度器是一种基于进程优先级的调度算法，它总是选择优先级最高的就绪进程运行。在 xv6 中，数值越小的优先级表示更高的优先级（例如，优先级5的进程比优先级10的进程先运行）。

## 实现原理

### 1. 系统调用

- **系统调用号**: 401 (在 `sysnum.h` 中定义)
- **系统调用名**: `set_priority`
- **功能**: 设置指定进程的优先级
- **参数**: 进程ID和优先级值 (必须 ≥ 1)
- **返回值**: 成功返回 0，失败返回 -1

### 2. 内核数据结构

在 `proc` 结构体中添加了以下字段:
```c
#ifdef SCHEDULER_PRIORITY
int priority;         // 进程的优先级
#endif
```

### 3. 核心函数

#### `sys_set_priority()`
- 位置: `arch/riscv/kernel/sysproc.c`
- 功能: 系统调用处理函数，设置指定进程的优先级
- 参数校验: 确保优先级值 ≥ 1

#### `priority_scheduler()`
- 位置: `arch/riscv/kernel/proc.c`
- 功能: 选择优先级最高的就绪进程运行
- 调用时机: 在调度器中调用

#### `priority_on_timer_tick()`
- 位置: `arch/riscv/kernel/proc.c`
- 功能: 处理时钟中断，在时间片耗尽时触发进程切换
- 调用时机: 在 `trap.c` 的时钟中断处理中调用

### 4. 调度器行为

- 默认调度器: 每次时钟中断时当前进程立即让出 CPU
- 优先级调度器: 总是选择优先级最高的就绪进程运行
- **CPU = 1 限制**: 在单核系统中，同一时间只能有一个进程运行，优先级调度器确保高优先级进程优先获得 CPU

## 编译与使用

### 编译选项
在 `Makefile` 中添加 `-DSCHEDULER_PRIORITY` 编译标志启用优先级调度器:
```makefile
CFLAGS += -DSCHEDULER_PRIORITY
```

### 用户程序使用
```c
#include "user/user.h"

int main() {
    // 设置当前进程的优先级为 5
    set_priority(getpid(), 5);
    
    // 执行任务...
    
    exit(0);
}
```

## 测试程序

`prioritytest.c` 提供了全面的测试用例，包括:
- 基本优先级调度测试
- 动态优先级变化测试
- 混合I/O和CPU密集型任务测试
- 饥饿测试
- 大量进程测试

## 注意事项

1. 优先级值必须 ≥ 1，否则系统调用返回 -1
2. 数值越小的优先级表示更高的优先级
3. 子进程继承父进程的优先级设置
4. 优先级调度器通过条件编译实现，不影响默认调度器
5. **CPU = 1 限制**: 在单核系统中，高优先级进程可能阻塞低优先级进程的执行，需要考虑饥饿问题
6. 为防止饥饿，可以定期提高等待时间长的低优先级进程的优先级

### 多核环境下的潜在问题

在CPU不为1的多核环境中，优先级调度器可能面临以下挑战：

1. **优先级反转**：低优先级进程持有高优先级进程所需的资源，导致高优先级进程被阻塞
2. **负载均衡**：如何在多核间合理分配不同优先级的进程
3. **缓存亲和性**：进程迁移可能导致缓存失效，影响性能

# MLFQ 调度器实现文档

## 概述

MLFQ (Multi-Level Feedback Queue) 调度器是一种多级反馈队列调度算法，它根据进程的行为动态调整优先级。MLFQ 旨在同时满足以下目标：

1. 快速响应交互式任务
2. 公平分配 CPU 时间给计算密集型任务
3. 避免进程饥饿

## 实现原理

### 1. 系统调用

- **系统调用号**: 402 (在 `sysnum.h` 中定义)
- **系统调用名**: `get_priority`
- **功能**: 获取指定进程的当前优先级
- **参数**: 进程ID
- **返回值**: 成功返回优先级值，失败返回 -1

### 2. 内核数据结构

在 `proc` 结构体中添加了以下字段:
```c
#ifdef SCHEDULER_MLFQ
int priority;         // 进程的当前优先级
int cpu_time;         // 在当前评估窗口内的CPU时间
int sleep_time;       // 在当前评估窗口内的睡眠时间
int eval_window;      // 评估窗口计数器
#endif
```

### 3. 核心函数

#### `sys_get_priority()`
- 位置: `arch/riscv/kernel/sysproc.c`
- 功能: 系统调用处理函数，获取指定进程的当前优先级
- 参数校验: 确保进程ID有效

#### `mlfq_scheduler()`
- 位置: `arch/riscv/kernel/proc.c`
- 功能: 选择优先级最高的就绪进程运行
- 调用时机: 在调度器中调用

#### `mlfq_on_timer_tick()`
- 位置: `arch/riscv/kernel/proc.c`
- 功能: 处理时钟中断，更新进程的CPU时间和优先级
- 调用时机: 在 `trap.c` 的时钟中断处理中调用

#### `mlfq_on_sleep()`
- 位置: `arch/riscv/kernel/proc.c`
- 功能: 处理进程睡眠，更新进程的睡眠时间
- 调用时机: 在进程进入睡眠状态时调用

#### `mlfq_adjust_priority()`
- 位置: `arch/riscv/kernel/proc.c`
- 功能: 根据进程的CPU/sleep比例调整优先级
- 调用时机: 在评估窗口结束时调用

### 4. 调度器行为

#### 4.1 优先级调整机制
MLFQ 根据进程在评估窗口内的 CPU 时间和睡眠时间比例调整优先级：

```
if (cpu_time > sleep_time) {
    // CPU密集型进程，降低优先级（增加数值）
    priority += (cpu_time - sleep_time) / MLFQ_PRIORITY_FACTOR;
} else {
    // I/O密集型进程，提高优先级（减少数值）
    priority -= (sleep_time - cpu_time) / MLFQ_PRIORITY_FACTOR;
}
```

#### 4.2 评估窗口
- 评估窗口大小：`MLFQ_EVAL_TICKS` (默认为 5 个时钟节拍)
- 每个评估窗口结束时，根据进程行为调整优先级
- 重置 CPU 时间和睡眠时间计数器

#### 4.3 时间片分配
- 高优先级进程（优先级 1-3）：获得 1-2 个时钟节拍的时间片
- 中等优先级进程（优先级 4-7）：获得 2-4 个时钟节拍的时间片
- 低优先级进程（优先级 8+）：获得 4-5 个时钟节拍的时间片

#### 4.4 防饥饿机制
- 最低优先级限制：`MLFQ_MAX_PRIORITY` (默认为 20)
- 定期提升长时间等待的低优先级进程的优先级
- 新进程初始优先级：`MLFQ_DEFAULT_PRIORITY` (默认为 5)

## 编译与使用

### 编译选项

## 测试程序

`test_proc_mlfq.c` 提供了全面的测试用例，包括:
- CPU密集型任务测试
- I/O密集型任务测试
- 混合型任务测试
- 长时间睡眠任务测试
- 中等CPU密集型任务测试

### 测试任务类型

1. **CPU密集型任务**：
   - 执行大量计算，很少睡眠
   - 优先级应逐渐降低（数值增大）
   - 完成时间应较晚

2. **I/O密集型任务**：
   - 频繁睡眠，很少计算
   - 优先级应逐渐提高（数值减小）
   - 完成时间应较早

3. **混合型任务**：
   - 计算和睡眠交替进行
   - 优先级应保持相对稳定
   - 完成时间应介于CPU密集型和I/O密集型任务之间

4. **长时间睡眠任务**：
   - 一次性长时间睡眠
   - 优先级应有适度提高
   - 完成时间取决于睡眠时长

## 性能优化建议

### 1. 调整任务参数
- **I/O密集型任务**：减少单次睡眠时间，增加睡眠频率
- **CPU密集型任务**：适当增加计算量，确保优先级有明显变化
- **混合型任务**：调整计算和睡眠比例，使优先级保持相对稳定

### 2. 调整MLFQ参数
- **评估窗口大小**：根据实际需求调整 `MLFQ_EVAL_TICKS`
- **优先级调整因子**：调整 `MLFQ_PRIORITY_FACTOR` 控制优先级变化幅度
- **时间片分配**：根据系统负载调整不同优先级的时间片大小

### 3. 监控和调试
- 添加优先级变化日志，观察进程优先级变化趋势
- 监控队列状态，了解进程在不同优先级队列间的移动
- 记录时间片使用情况，分析调度效率

## 注意事项

1. 优先级值越小表示优先级越高
2. 子进程继承父进程的优先级设置
3. MLFQ调度器通过条件编译实现，不影响默认调度器
4. 评估窗口大小应根据系统特性进行调整
5. 优先级调整幅度应适中，避免过度优先或过度惩罚
6. 在多核环境中，需要考虑负载均衡和缓存亲和性问题
